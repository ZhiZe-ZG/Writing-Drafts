该字体的收集主要关注已发布的，可以直接使用的字体，而不是以字体开发等为关注焦点。

## “字体”的英文对应

一般来说，“typeface”是指一套用于印刷的铅字，而“font”是指一定大小、字重和风格之下的铅字。也就是说一套“typeface”可能由若干“font”构成。在字体数字化的时候，文件格式最初是以“font”为单位，因此“font”成为了计算机上“字体”的一般说法。

在此基础上，风格近似，参数不同的一组 font 则被以“font family”的名义收录在一起。一些字体文件格式以及相关技术也使用“font family”来作为技术术语。但是，实践当中，“font family”的收录往往又比较随意，不一定能真正把风格近似，参数不同的 font 收录在一起，因此在该笔记中以“typeface”为单位收录字体，同时其 font 组成由知则参考字体情况划定。

## 字体名称和字体分类

由于历史原因，字体的命名相对混乱，这主要由如下几方面因素导致：

1. 最初的数字化字体文件对应铅字的“font”概念，因此一个“font”文件中的光学字号、字重、字宽等应当都是已经确定好的。但是随着技术进步，出现了可变字体这种自行描述方式，但是文件封装格式（如 OpenType）是基于“font”时代发展而来的。
2. 西文字体中 roman 和 italic 往往需要组合使用，因此在字体制作的时候这两种风格常常成对制作，但是从字形结构和装饰来说一个商品字体中的 roman 和 italic 两者之间的差距可能比不同的 roman 字体之间还大。
3. 东亚脚本中不同地区正字法不同导致的笔画写法差别。其本质只是同一个字的不同替代字形的问题，但是由于数量巨大，往往无法使用字体文件（如 OpenType）中的替代字形特性处理，只能制作成不同字体文件。
4. 字体编码方案（如 Unicode）的发展以及字体文件格式（如 OpenType）的限制，导致不同脚本字符难以同时收录。迫使收字量较大的字体分成多个文件制作。此外，还有很多字体一开始仅覆盖部分脚本或字集，随着后续开发增补字集，形成了多种版本。
5. 字体制作、发布、复刻关系混乱，导致多种字体版本。
为了处理以上问题，提出以下准则：

1. 以发布版本为准，区分不同厂商或者设计者的近似字体作品。如有必要，在字体名称中追加区分性补充内容。
2. 尽量不因暂时技术限制而划分不同字体。例如不因视觉字号（optical size）、字重（weight）、字宽（width）、倾斜（oblique）等而划分不同字体。这些信息在静态字体中用字体名称参数区分，在可变字体中尽量用字体内部参数区分。圆角（rounded）、轮廓（outline）等风格虽然目前还没有广泛地作为字体内参数，但是理论上可以用相对简单的算法实现，所以也归类为名称参数或者内部参数。
3. 东亚脚本不同正字法的笔画区别视同西文字体中字母的不同变体写法处理。如果可以使用字体格式的内部参数（如 OpenType 的替代字形）处理的，尽量用内部参数处理。实在处理不了做成不同参数的，用字体名称参数区分。
4. 技术性更新作为值得存档的不同版本进行收录。一般的版本更新时，使用新版本直接替代旧版本。但是可变字体替代静态字体时，静态字体可以创建一个专门文件夹用于存档。
5. 增加收字分为两种情况讨论。如果作为原有字体的补充，不做大量的重合字体，直接补充到原有字体中（列举在原字体文件名称后边作为追加）。如果包含原有字体则作为全新的版本或者全新字体。特别说明，如果一个字体是原字体的补充字体，但是补充的主要是 Unicode 的 PUA （Private Use Area），也视作补充内容。如果对于 PUA 存在多个彼此冲突的补充，也一律视作补充内容。这些冲突是字体文件格式限制带来的，而且在一定程度上应该由排版引擎处理。所以这些冲突不是字集本身的设计问题，应当予以常规收录。
7. 有字形变化的 italic 字体视作类似衬线（serif）、无衬线（sans）之类的风格变化乃至设计变化。因此视作不同的字体来处理。
